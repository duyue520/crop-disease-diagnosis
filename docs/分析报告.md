## 一、数据集分析

### 1.1 规模与分布

| 指标 | 数值 |
|---|---|
| 图片总数 | **55,448 张** |
| 类别数 | **39**（38 类病害/健康 + 背景类口径见 config） |
| 作物种类 | **15**（苹果、蓝莓、樱桃、玉米、葡萄、橙子、桃子、甜椒、马铃薯、树莓、大豆、南瓜、草莓、番茄…） |
| 单类最多 | **5,507 张** —— Orange___Haunglongbing (Citrus_greening 柑橘黄龙病) |
| 单类最少 | **152 张** —— Potato___healthy（马铃薯健康） |
| 不平衡比 | **约 36 : 1** |

**样本最多 Top3**：柑橘黄龙病 5,507 ｜ 番茄黄化曲叶病毒 5,357 ｜ 大豆健康 5,090
**样本最少 Top3**：马铃薯健康 152 ｜ 苹果雪松锈病 275 ｜ 桃子健康 360

### 1.2 分布问题的三层影响

1. **训练层面**：`CrossEntropyLoss` 无权重时，模型会偏向高频类；低频类的梯度贡献被淹没。
2. **评估层面**：总体准确率被高频类主导 —— 5,507 张的类错 10% 只影响总准确率约 1%；152 张的类全错也只影响 0.27%。**因此 99.4% 的总体准确率不能证明少见病识别能力**。
3. **使用层面**：马铃薯/苹果/桃子健康样本少，实践中"健康 → 误报为病害"的概率可能偏高，直接影响农户信任。

### 1.3 数据划分方式（⚠️ 关键风险）

当前实现为：

```python
train_dataset, val_dataset = random_split(full_dataset, [len - val_size, val_size])   # 8:2
```

**风险**：PlantVillage 类数据集存在大量"同一片叶子的不同角度/增强版本"，随机切分会把近乎重复的图片同时放进训练集与验证集 → **验证准确率偏乐观（数据泄漏式虚高）**。

**建议（P0）**：
- 若数据源含原始图片 ID / 采集批次 → 按 **Group Split**（同组只进一个集合）；
- 或采用数据集官方 train/test 划分；
- 报告时明确标注切分方式；预期诚实指标会比 99.4% 低 1~3 个百分点，**这是好事**（数字可信才能指导决策）。

## 二、训练过程分析

### 2.1 逐轮指标（真实数据）

| Epoch | train_loss | val_loss | train_acc (%) | val_acc (%) |
|---|---|---|---|---|
| 1 | 0.30 | 0.34 | 90.53 | 89.83 |
| 2 | 0.15 | 0.12 | 95.24 | 96.07 |
| 3 | 0.13 | 0.08 | 95.89 | 97.38 |
| 4 | 0.11 | 0.13 | 96.50 | 95.44 |
| 5 | 0.09 | 0.10 | 97.07 | 96.72 |
| 6 | 0.09 | 0.06 | 97.22 | 98.12 |
| 7 | 0.08 | 0.11 | 97.65 | 96.19 |
| **8** | **0.02** | **0.02** | **99.43** | **99.31** |
| 9 | 0.01 | 0.02 | 99.78 | 99.40 |
| 10 | 0.01 | 0.02 | 99.86 | **99.40** |

（`StepLR(step_size=7, gamma=0.1)`：第 8 轮起学习率降为 1e-4）

### 2.2 四条可读出的结论

1. **收敛极快**：第 2 轮就到 96%，说明 ImageNet 预训练特征对叶片任务迁移性极好，也侧面说明任务本身不难。
2. **第 3~7 轮验证准确率抖动**（97.38 → 95.44 → 96.72 → 98.12 → 96.19）：`Adam + lr=1e-3` 在这个阶段偏大，属于典型的"在最优附近来回跳"。
3. **降 lr 是决定性一步**：第 7 → 8 轮，val_acc 从 96.19% 直接跳到 99.31%。**说明前 7 轮的学习率过高，训练预算主要花在"压噪声"而非"提精度"上。**
4. **过拟合程度可控**：末轮 train 99.86% vs val 99.40%，差 **0.46 个百分点**，val_loss 稳定在 0.02 —— 没有明显过拟合，数据增强策略起了作用。

### 2.3 训练策略的改进空间（P1）

| 项 | 现状 | 建议 | 预期收益 |
|---|---|---|---|
| 学习率调度 | StepLR(7, 0.1)，只降一次 | **CosineAnnealing** 或 `OneCycleLR` 预热+退火 | 减少 §2.2 的抖动，收敛更稳 |
| 训练轮数 | 10（第 8 轮才吃到降 lr 红利） | 20~30 轮 + 早停 | 曲线仍在下降，多训有益 |
| 损失函数 | 纯 CrossEntropy | + **label smoothing=0.1**（防过自信）/ 类别加权 / Focal Loss | 少数类提升，置信度校准 |
| 类别不平衡 | 未处理 | `WeightedRandomSampler` 或 `class_weight = 1/freq` | 少数类召回提升 |
| 精度/显存 | 未开 AMP | `torch.cuda.amp` + EMA 权重平均 | 训练更快更稳（有 GPU 时） |
| 切分 | random_split | 分组切分（见 §1.3） | 指标可信度 ↑ |

## 三、评估结果分析

### 3.1 现有结果

- **验证集准确率：99.40%**（10 epoch，20% 验证集）
- 产物：`outputs/training_curves.png`、`confusion_matrix.png`、`class_metrics.png`、`dataset_distribution.json`

### 3.2 这个 99.4% 意味着什么（重要）

| 参照 | 说明 |
|---|---|
| 任务难度 | PlantVillage 是**实验室单叶、背景单一、光照均匀**的图像集；文献中 ResNet18/ResNet50 在该集上普遍 98~99%+ |
| 结论 1 | **在本数据集上，99.4% 属于"到达数据集上限"的水平** —— 说明训练实现正确、超参合理，模型不是瓶颈 |
| 结论 2 | **它不能证明"田间可用"**。实验室→真实场景存在域偏移（背景/光照/遮挡/多叶/手机画质），同类模型在田间数据上常见掉到 60~85% |
| 结论 3 | 由于 §1.3 的切分风险，99.4% 可能**偏乐观**；换成无泄漏切分后若下降 1~3pp 属正常，应以新数字为准 |

### 3.3 必须补看的指标（⚠️ 待核对）

总体准确率会掩盖少数类问题，请打开并核对以下两张图（方法附后）：

## 四、严重度模块分析（⚠️ 启发式，非模型）

`server/utils/severity.py` 用 HSV 颜色先验估算病斑占比：

```
绿色掩码 H∈[30,90] → 健康组织
叶片掩码 S>20 且 V>30 → 排除背景
严重度 = (叶片 − 绿色) / 叶片 × 100%
分级：<5% 轻 ｜ 5–20% 中 ｜ ≥20% 重
```

**合理性**：对"绿色叶片 + 褐色/黄色病斑"这一最常见情形，估算方向正确，且实现零成本、可解释。

**已知失效场景（必须让使用者知道）**：
1. **紫色/红色叶品种**：健康组织不落在绿色 H 区间 → 严重度虚高；
2. **土/砖红背景**：S、V 均高 → 被并入"叶片"，分母偏大、病斑被稀释；
3. **强阴影 / 过曝**：V 阈值失效；
4. **病斑为白色/灰色霉层**（如部分 Leaf Mold）：与高亮背景难分；
5. **小图**：`leaf_mask < 100` 像素时直接返回"轻度 0%" —— 是保护性退化，但用户会看到"0% 轻度"，语义上应改为"无法评估"。

**改进路径（P1/P2）**：
- 最小改动：把 `<100` 分支的返回改为 `unknown / 无法评估`，并在 UI 提示拍摄要求；
- 中等：先做**叶片分割**（颜色+形态学，或轻量 U-Net），再在叶片区域上统计病斑；
- 彻底：标注少量"严重度等级"数据，训练回归/分级模型，并用人工标注校准阈值。

## 五、模型强度评估（直接回答"强不强"）

| 维度 | 评级 | 依据 |
|---|---|---|
| 在**本数据集**的识别精度 | ✅ 强 | 99.40% val_acc，已达该数据集常规上限；10 轮即收敛 |
| 训练实现正确性 | ✅ 良好 | 迁移学习+增强+早停+最优权重保存+类别映射落盘，工程规范 |
| 数据切分可信度 | ⚠️ 需修正 | `random_split` 存在同源近重复泄漏风险，99.4% 可能偏乐观 |
| **田间泛化能力** | ❌ 短板 | 无田间数据训练/验证；域偏移会让准确率大幅下降 |
| 类别不平衡处理 | ⚠️ 需处理 | 36:1 不平衡 + 未加权；少数类表现未知 |
| 非叶片/未知输入处理 | ❌ 缺失 | 无 OOD 拒识，拍到桌面/人脸也会输出某个"病名" |
| 严重度可靠性 | ⚠️ 启发式 | HSV 规则，非模型；5 类失效场景已知 |
| 推理效率/部署 | ✅ 良好 | ResNet18 + ONNX + CPU 可跑，几十毫秒/张；可再量化瘦身 |

**一句话结论**：
> 这是一套**工程实现规范、在实验室数据集上接近满分**的项目；作为教学/演示/毕业设计/内部工具**已经完全够用**，不需要大改。
> 但如果目标是**让农户在田里拍照就能信**,当前版本还不够——缺的不是"更强的网络"，而是**无泄漏评估 + 少数类处理 + 拒识机制 + 田间数据**。

## 六、改进路线图（按投入产出排序）

### P0 · 不做就不能上线（各 0.5~1 天）

1. **换成无泄漏切分**，重新评估并如实公布新指标（可能 97~98%）
2. **加 OOD 拒识**：softmax 熵阈值 / 最大概率阈值 / 背景类；输出"未识别为叶片，请重拍"
3. **拉出 per-class F1**，把少数类（<400 张的 5 个类）结果公示；若明显偏低，加类别权重重训
4. **严重度小图分支语义修正**：`无法评估` 而不是 `轻度 0%`

### P1 · 让它真的能用（各 2~3 天）

5. **域泛化套餐**：加入田间/手机拍摄数据（哪怕每类 50~100 张）+ RandAugment / CutMix / 背景替换 + **TTA（多尺度/翻转）推理**
6. **训练策略升级**：CosineAnnealing + label smoothing + 25 epoch + EMA（本数据集收益有限，主要提升稳健性与校准度）
7. **严重度重构**：叶片分割（轻量 U-Net 或强颜色+形态学）后统计病斑
8. **置信度校准**：温度标定（temperature scaling），让"92%"真的约等于 92% 正确率

### P2 · 体验与成本（各 1~2 天）

9. **权重瘦身**：int8 量化（42.7MB → ~11MB）、合并重复的两个 ONNX；模型启动预热
10. **骨干替换**：移动端用 MobileNetV3-Small（2.5M 参数）；追求精度用 EfficientNet-B0 / ConvNeXt-Tiny
11. **上线监控与回流**：记录预测分布与低置信样本，人工纠错后回流训练集（主动学习闭环）
12. **服务加固**：`uvicorn --workers`、限流、上传体积/格式校验（防超大图打满内存）
