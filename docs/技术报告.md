## 1. 系统总览

系统由三部分组成，可独立使用，也可组合部署：

| 模块 | 技术栈 | 职责 |
|---|---|---|
| 训练侧 | PyTorch + torchvision | 数据加载/增强、训练、评估、导出 ONNX |
| 推理服务 | FastAPI + ONNX Runtime | 提供 `/api/predict` 等接口，加载 ONNX 权重推理 |
| 前端 | Vue | 上传图片、展示病名/置信度/热力图/严重度、历史记录、批量导出 |

数据流：

```
用户上传图片
  → FastAPI 接收 (multipart)
  → predict_service：预处理 → 推理（ONNX 优先，缺 ONNX 回退 PyTorch）
  → softmax Top-3 → 类别中英映射 (config.CLASS_CN)
  → severity.estimate_severity：HSV 病斑占比 → 轻/中/重
  → JSON 响应（含防治建议、热力图 base64）
```

## 2. 神经网络：ResNet18 迁移学习

### 2.1 结构细节（224×224×3 → 39 类）

| 阶段 | 结构 | 输出尺寸 | 通道 |
|---|---|---|---|
| stem | Conv 7×7, stride 2 + BN + ReLU + MaxPool 3×3/2 | 56×56 | 64 |
| layer1 | 2 × BasicBlock（3×3 conv ×2，恒等捷径） | 56×56 | 64 |
| layer2 | 2 × BasicBlock（首个 stride=2） | 28×28 | 128 |
| layer3 | 2 × BasicBlock（首个 stride=2） | 14×14 | 256 |
| layer4 | 2 × BasicBlock（首个 stride=2） | 7×7 | 512 |
| head | GlobalAvgPool → FC(512 → 39) | 39 | — |

**BasicBlock**：`y = ReLU(F(x, {Wi}) + x)`，其中 `F` 为两层 3×3 卷积 + BN。捷径分支在通道数变化时用 1×1 卷积 + stride 对齐。

**为什么这样有效**：
- 恒等捷径让梯度沿"高速公路"回传，18 层也不会梯度消失/退化；
- GlobalAvgPool 代替大 FC，参数少、抗过拟合，且对输入尺寸变化更鲁棒；
- 11.2M 参数 / 1.8 GFLOPs，CPU 单张推理几十毫秒量级，适合低成本部署。

### 2.2 迁移学习设定

```python
model = get_model(model_name="resnet18", num_classes=39,
                  pretrained=True,          # 加载 ImageNet 权重
                  freeze_backbone=False)    # 全量微调
```

- ImageNet 特征（边缘/纹理/颜色统计）对叶片病斑同样有效，省去从零训练的数据需求；
- 全量微调而非只训分类头：叶片域与自然图像域差异大，解冻全部卷积层收益明显；
- 分类头随机初始化，训练中与骨干一同收敛。

### 2.3 超参数与训练策略

| 项目 | 值 | 依据 |
|---|---|---|
| Loss | `CrossEntropyLoss` | 单标签多分类标准选择 |
| Optimizer | `Adam(lr=1e-3)` | 迁移学习常用，收敛快、对 lr 不敏感 |
| Scheduler | `StepLR(step_size=7, gamma=0.1)` | 第 7 epoch 降 lr 后验证准确率从 96.2% 跃升至 99.3%（见分析报告） |
| Batch | 32 | 显存/内存与收敛稳定性的折中 |
| Epochs | 10 | 配合 EarlyStopping（监控 val_acc） |
| 权重保存 | 保存验证集最优 + 最后一轮（含 `class_to_idx`/`idx_to_class`） | 保证部署时类别顺序可复现 |

**Checkpoint 内容**（关键工程细节）：除了 `model_state_dict`，还保存类别映射与训练历史，避免"模型与类别表错位"这一常见事故。

```python
torch.save({
    "model_state_dict": model.state_dict(),
    "class_to_idx": full_dataset.class_to_idx,
    "idx_to_class": full_dataset.idx_to_class,
    "classes": full_dataset.classes,
    "history": history,
    ...
}, best_model_path)
```

### 2.4 数据管线与增强

`data/dataset.py` 使用 `ImageFolder` 约定（**目录名即类别名**），并以 `random_split` 按 8:2 划分。

训练增强（每条都对应真实拍摄变化）：

| 增强 | 参数 | 应对场景 |
|---|---|---|
| Resize | 256×256 | 统一大尺度 |
| RandomResizedCrop | 224, scale=(0.7, 1.0) | 叶片只占局部、病斑取景差异 |
| RandomHorizontalFlip | p=0.5 | 任意摆放方向 |
| RandomVerticalFlip | p=0.2 | 倒置拍摄 |
| RandomRotation | ±25° | 手持角度抖动 |
| ColorJitter | 0.3/0.3/0.2/0.1 | 阴天/正午、白平衡差异 |
| Normalize | ImageNet mean/std | 与预训练权重统计一致（**必须一致**） |

验证/推理：`Resize(224) → ToTensor → Normalize`（确定性，无随机性）。

### 2.5 训练循环与早停

- `train_one_epoch` / `validate_one_epoch`（`utils/train_utils.py`）返回 loss 与准确率；
- `EarlyStopping` 在验证指标连续不提升时终止并回滚最优权重；
- 每轮记录 `train_loss/val_loss/train_acc/val_acc`，写入 `outputs/training_history.json`；
- `plot_utils` 绘制训练曲线、混淆矩阵、每类指标（`outputs/*.png`）。

## 3. ONNX 导出与推理服务

### 3.1 导出

训练完成/评估通过后导出 ONNX（`weights/model.onnx`、`weights/best_model.onnx`），推理时：

```python
# server/services/predict_service.py（要点）
state = torch.load(MODEL_PATH, map_location=device, weights_only=True)  # 兜底路径
onnx_path = MODEL_PATH.replace(".pth", ".onnx")
if os.path.exists(onnx_path):
    import onnxruntime as ort
    _onnx_session = ort.InferenceSession(onnx_path, providers=["CPUExecutionProvider"])
```

- **ONNX 优先、PyTorch 回退**：部署环境不必装完整 torch 也能推理（可省数百 MB 依赖）；
- 推理设备默认 CPU（兼容性最好，无需 CUDA 环境）。

### 3.2 预处理一致性（易错点）

推理侧必须与训练侧验证管线**完全一致**：

```python
T.Resize((224, 224))                    # 不用 RandomResizedCrop
T.ToTensor()
T.Normalize(mean=[0.485, 0.456, 0.406],  # ImageNet 统计，不可改
            std=[0.229, 0.224, 0.225])
```

不一致会导致"训练 99%、线上 60%"类事故。

### 3.3 严重度估算（启发式）

`server/utils/severity.py`：

```
HSV 绿色掩码  H∈[30,90]            → 健康组织
叶片掩码      S>20 且 V>30          → 排除背景（像素数 <100 视为无叶片）
病斑 = 叶片 − 绿色
严重度% = 病斑 / 叶片面积 × 100
分级： <5% 轻度 ｜ 5–20% 中度 ｜ ≥20% 重度
```

**性质说明**：这是基于颜色先验的**快速估算**，不是分割网络输出。对"紫色/红色叶品种、土背景、强阴影"会偏大或偏小；`<100` 像素的保护分支用于避免小图除零。生产环境建议替换为叶片分割模型或引入面积校准。

## 4. 接口与部署

### 4.1 接口

| 方法 | 路径 | 请求 | 响应要点 |
|---|---|---|---|
| POST | `/api/predict` | `multipart/form-data: file` | `disease_name / disease_cn / confidence / top3 / severity / severity_label / heatmap` |
| POST | `/api/predict/batch` | 多文件 | 逐张结果数组 |
| GET | `/api/health` | — | 服务与模型加载状态 |

### 4.2 部署方式

**方式 A：本地/服务器直接跑**

```bash
pip install -r requirements.txt
cd server && uvicorn main:app --host 0.0.0.0 --port 8000
```

**方式 B：Docker（推荐）**

```bash
cp .env.example .env      # 改 SECRET_KEY
docker compose up -d      # server/Dockerfile 构建，weights 只读挂载，数据卷持久化
```

`docker-compose.yml` 关键点：
- `PORT 8000` 暴露；
- `./weights:/app/weights:ro` 只读挂载，防止容器写坏模型；
- `disease_data` 命名卷持久化数据库；
- `restart: unless-stopped` 自愈。

**方式 C：前端独立部署**：`frontend/` 构建为静态资源，反向代理 `/api` 到推理服务。

### 4.3 性能与优化空间

| 项目 | 现状 | 可优化 |
|---|---|---|
| 权重体积 | 2 × 42.7MB（fp32 ONNX） | int8 量化 → 约 11MB；两个权重若内容一致可只留一个 |
| 推理速度 | CPU 可用 | ONNX Runtime 多线程 / OpenVINO / TensorRT（有 GPU 时） |
| 并发 | 单进程 uvicorn | `--workers N` + 前置 nginx；批处理走 `/predict/batch` |
| 冷启动 | 首次请求加载模型 | 启动时预热（启动钩子里跑一次空推理） |

## 6. 工程注意事项

1. **类别顺序必须绑定权重**：部署时读 checkpoint 里的 `idx_to_class`，不要依赖目录遍历顺序。
2. **预处理必须与训练一致**：Resize/Normalize 参数改动需同步两侧。
3. **不要把密钥写进代码**：`SECRET_KEY` 等从环境变量读取（`.env`，已被 `.gitignore` 忽略）。
4. **模型文件体积**：仓库含 42.7MB × 2 的 ONNX，克隆较慢；如需频繁拉取建议使用 Git LFS 或改从 Release 下载。
5. **CUDA 兼容性**：如遇新显卡不被当前 torch 支持，可先用 CPU 推理（本项目默认即是）。
